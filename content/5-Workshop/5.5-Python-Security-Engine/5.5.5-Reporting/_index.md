### Overview

After Security Checks are performed and the Security Engine processes the generated Findings, the project needs a mechanism to present and store the results.

The **Reporting** functionality is organized under:

~~~text
python/reporters/

├── console.py
└── json_reporter.py
~~~

Generated reports are stored under:

~~~text
output/reports/

├── history/
└── latest.json
~~~

![ASAU](/images/01/image_253.png)

### 1. Role of Reporting

Reporting is the output layer of the Security Engine. It converts processed security results into information that can be viewed or stored.

~~~text
Security Checks

       ↓

    Finding

       ↓

Security Engine

       ↓

   Reporting

    /       \

   ↓         ↓

Console      JSON
~~~

The results can either be displayed directly in the console or stored in JSON format.

### 2. `console.py`

File:

~~~text
python/reporters/console.py
~~~

is responsible for displaying Security Engine results in the terminal.

~~~text
Security Engine

      ↓

  console.py

      ↓

   Terminal
~~~

### 4. `latest.json`

The project stores the latest report at:

~~~text
output/reports/latest.json
~~~

This file represents the most recent security report generated by the Security Engine.

~~~text
Security Engine

      ↓

json_reporter.py

      ↓

latest.json
~~~

![ASAU](/images/01/image_251.png)

### 5. Report History

The project also contains:

~~~text
output/reports/history/
~~~

This directory is used to preserve previous reports.

~~~text
output/reports/

│
├── latest.json
│
└── history/
    └── Previous Reports
~~~

![ASAU](/images/01/image_261.png)

Maintaining historical reports allows previous security results to be reviewed and compared with newer results.

### 6. Console and JSON Reporting

The two reporters serve different purposes:

| Reporter | Purpose |
|---|---|
| `console.py` | Displays results in the terminal |
| `json_reporter.py` | Exports results as JSON |

The workflow is:

~~~text
                    Finding

                       ↓

                Security Engine

                       |

                +------+------+
                |             |
                ↓             ↓

           console.py    json_reporter.py
                |             |
                ↓             ↓
             Terminal     latest.json
                              |
                              ↓
                           history/
~~~

### 7. Overall Reporting Workflow

The complete Reporting workflow is:

~~~text
Managed Nodes

      ↓

Security Checks

      ↓

Finding

      ↓

Security Engine

      ↓

Reporters

   /       \

  ↓         ↓

Console     JSON

  |          |

  ↓          ↓

Terminal   latest.json

              |

              ↓

           history/
~~~

Reporting represents the transition from internal Security Engine results to information that users can observe, store, and review.

### Result

After implementing Reporting, the project can provide security results in two main forms:

~~~text
Python Security Engine

          ↓

       Finding

          ↓

      Reporting

       /     \

      ↓       ↓

  Console     JSON

     |          |

     ↓          ↓

 Terminal   latest.json

                |

                ↓

             history/
~~~

This structure allows security results to be both **displayed directly** and **stored as structured data** for later analysis and reference.
